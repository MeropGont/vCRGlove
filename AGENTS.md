# Project Collaboration

- After a major change, update the relevant feature documentation and test checklist, keeping implemented behaviour separate from proposals and unverified hardware checks.
- Treat the backlog workbook as closed by default. Ask the user to save/close it only when an Excel lock file or another reliable check shows it is open; preserve its formatting and manual edits.
- Keep Markdown as the editable documentation source and regenerate `docs/vCRGlove_Handbook.pdf` after changing its source chapters. The build command is in `docs/README.md`. Do not maintain a separate hand-edited PDF copy.
- Obtain user approval before implementing a new major stage unless that stage has been explicitly delegated. Preparing study-information copy does not authorize app changes or consent handling.
- Confirm the authoritative source/version before changing study information. Preserve German legal wording; omissions and translations need explicit approval. For the October 2026 implementation, the user authorized the newest dated Word source, omission of its lab-video paragraph, and a faithful English translation, with legal names retained. This does not authorize future legal rewrites. Keep ethics source files and approval drafts out of Git unless separately authorized.
